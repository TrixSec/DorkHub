# Contributing to DorkHub

First off, thank you for considering contributing to DorkHub! It's people like you that make DorkHub such a great tool for the security community.

## How to Contribute

### 1. Dork Quality Standards
We prioritize **quality over quantity**. Please ensure your submissions are:
- **Unique**: Check if the dork already exists. We want to avoid common noise.
- **Valuable**: Does this dork find something genuinely useful or impactful?
- **Descriptive**: When submitting, please provide context on what the dork finds.

### 2. Format
Right now, dorks are added as text files. Please ensure you are adding your dorks to the appropriate category folder (e.g., `sqli/`, `cloud/`, etc.). 

If you are proposing a new category, please create a new folder (using `kebab-case`) and add a `README.md` to that folder explaining what the category is.

### 3. Submitting Changes
1. Fork the repository.
2. Create a new branch (`git checkout -b feature/new-dorks`).
3. Add your dorks to the relevant file(s).
4. Commit your changes (`git commit -am 'Add high-value AWS dorks'`).
5. Push to the branch (`git push origin feature/new-dorks`).
6. Open a Pull Request.

## Review Process
Our team will review your Pull Request to ensure the dorks meet our quality standards and are not duplicates. We may ask for clarifications or suggest edits.

Thank you for contributing!
